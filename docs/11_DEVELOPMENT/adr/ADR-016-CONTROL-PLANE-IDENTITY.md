# ADR-016: Control-Plane Identity, Durability, and Event Contracts

Date: 2026-07-31  
Status: Accepted

## Context

ETLantic 0.39 (CP1) establishes an embeddable, versioned control-plane API and
canonical request identity. Without a frozen vocabulary, callers and stores
will invent incompatible tenant fields, treat path or header claims as
authority, and leak cross-tenant existence through error codes or list counts.

Without durable acceptance and versioned event/cursor shapes, API workers will
rely on process-local globals or FastAPI `BackgroundTasks` for heavy work —
patterns that cannot survive restart or multi-worker deployment and that block
the 0.41 durable-execution migration.

This ADR locks identity types, correlation and idempotency key shapes,
non-enumeration policy, durable submission receipts, event/SSE wire shapes,
authority rules for tenant claims, the CP1 vs 0.43 graduation boundary, and
landing-watch placement for the 0.39 control-plane program.

## Decision

### Identity vocabulary

Freeze these exact type names before route implementation. They are opaque
references and context carriers — not directories, display labels, or
credentials.

| Type | Meaning | Required properties |
|---|---|---|
| `Principal` | Authenticated human or workload | Issuer-qualified immutable subject; no embedded credentials |
| `TenantRef` | Top-level authorization / billing boundary | Opaque immutable tenant id; never inferred from display name |
| `WorkspaceRef` | Tenant-owned authoring and operations namespace | Opaque workspace id; unique within tenant |
| `EnvironmentRef` | Deployment / promotion slice | Opaque environment id bound to policy and approved targets |
| `SecurityDomain` | Data-handling and reuse boundary | Opaque domain id preserved in plans, artifacts, caches, and execution envelopes |
| `ControlPlaneContext` | Server-derived request scope | Immutable composition of principal, tenant, workspace, environment, security domain, and correlation data; request-scoped |

`ControlPlaneContext` is constructed only after authentication and trusted
server-side membership mapping. It is frozen for the lifetime of the request.
Serialized forms must not contain resolved secrets, source rows, or display
names used as authority.

Candidate wire schema id: `etlantic.control_plane.context/1`.

### Correlation and idempotency keys

**Correlation id**

- Wire name: `correlation_id` (JSON) / `X-Correlation-ID` (HTTP, when present).
- Value: opaque non-empty string (UUID or ULID preferred); generated by the
  server when the client omits one.
- Scope: request-wide; echoed on accept receipts, problem details, audit
  evidence, and run events.
- Correlation ids are not authorization material.

**Scoped idempotency key**

- Client header: `Idempotency-Key` (opaque client token).
- Effective store key is **server-scoped**, never the raw header alone:

  ```text
  (tenant_id, workspace_id, principal_subject, operation, idempotency_key)
  ```

- Same scoped key + same normalized request fingerprint → return the original
  authorized accept receipt.
- Same scoped key + different fingerprint → conflict (do not create a second
  acceptance).
- Keys from another tenant/workspace/principal never collide and never
  authorize replay across scopes.

Candidate wire schema id: `etlantic.control_plane.idempotency/1`.

### Non-enumeration and 403 vs 404

Authorization precedes existence lookup, count, search, pagination, artifact
access, and event subscription. Repository APIs that take only a global
resource id without `ControlPlaneContext` are non-conforming for tenant-owned
resources.

Consistent HTTP policy for ordinary tenant routes:

| Situation | Status | Rationale |
|---|---|---|
| Caller not authenticated | `401` | Challenge / reject; no resource disclosure |
| Authenticated, but resource is outside the caller's authorized tenant/workspace scope (whether or not it exists) | `404` | Deny existence disclosure across tenants and unauthorized workspaces |
| Authenticated and in-scope, but action is forbidden on a known authorized resource | `403` | Permission failure without cross-tenant leakage |
| Authenticated, in-scope, resource absent | `404` | Ordinary not-found |

List, search, cursor, and SSE operations filter **before** pagination and
serialization. They must not reveal unauthorized counts, identifiers, cursor
positions, timing distinctions, or differentiated error detail that would
disclose another tenant's resources.

Cross-tenant administration uses separate routes, credentials, policy, and
audit events — never an accidental extension of tenant routes.

### Durable submission

Submission is a control-plane transaction, not a background function call.

- Return `202 Accepted` only after durable acceptance commits (accept receipt
  persisted in an injected repository/queue boundary).
- Accept receipt (minimum fields): `run_id` (or submission id), `status`
  (`accepted`), scoped context fingerprint, correlation id, idempotency record
  reference, `status_url`, `events_url`, and schema version.
- Candidate wire schema id: `etlantic.control_plane.accept_receipt/1`.
- FastAPI `BackgroundTasks` must not perform heavy pipeline work or act as the
  acceptance store.
- Process-local globals, module singletons, and in-process dicts are not an
  accepted multi-worker acceptance store. In-memory fakes are allowed only in
  tests and explicitly labeled local demos.
- If durable state cannot commit, do not return `202`.

Design accept-receipt and outbox fields so 0.41 can add leases, fencing tokens,
and recovery without a breaking reset of `/1` readers (additive fields or a
documented `/2` with dual-read).

### Event envelope and SSE cursor

Run/event observation uses a versioned envelope distinct from compliance audit
evidence.

**Event envelope** (`etlantic.control_plane.event/1`):

| Field | Role |
|---|---|
| `schema` | Envelope schema id |
| `event_id` | Opaque durable event id |
| `sequence` | Monotonic per-scope sequence (tenant/workspace/run as applicable) |
| `type` | Stable event type string |
| `occurred_at` | Timestamp |
| `correlation_id` | Request/run correlation |
| `causation_id` | Optional upstream event id |
| `scope` | Tenant/workspace/environment refs (no credentials) |
| `run_id` | Submission / run identity when applicable |
| `payload` | Bounded, redacted, secret-free data |

**SSE cursor** (`etlantic.control_plane.sse_cursor/1`):

- Opaque, tenant- and workspace-scoped resume token.
- Authorization is revalidated on subscribe and resume.
- Resume must not observe another tenant's events or silently skip an
  authorization change; expired or unauthorized cursors fail closed with the
  non-enumeration policy above.
- History fallback reads the same scoped event store; cursor shape must remain
  migratable when 0.41 adds durable multi-worker event history.

### Path and header tenant claims are never authority

Tenant, workspace, or environment identifiers supplied in paths, headers,
query parameters, or request bodies are **routing claims only**. They never
override authenticated membership, policy decisions, or the server-derived
`ControlPlaneContext`. Spoofed claims that disagree with context are denied
under the non-enumeration policy.

### CP1 is not production multi-tenant

0.39 (CP1) is an incubation foundation: typed API, identity, authorization
hooks, durable acceptance contracts, and resumable events. It does **not**
claim production multi-tenant isolation. That claim remains gated to **0.43**
after CP1–CP4 pass as an integrated system.

Release notes and exit evidence must state this boundary explicitly.

### Landing watch outside core

Long-lived directory-watch loops and file-drop sensors remain **outside**
ETLantic core. In 0.39 they may compose as submitters that call the durable
submission API against the same 0.38 snapshot/incremental landing-zone
bindings. Watchers must not embed file contents in plans and must not become a
third pipeline authoring kind.

## Consequences

- Wave 1 identity models and repository protocols must use the frozen type
  names and require `ControlPlaneContext` on every tenant-owned method.
- HTTP adapters map denials through the 401 / 403 / 404 policy above; tests
  cover two-tenant and two-workspace non-enumeration for every operation.
- `etlantic-fastapi` returns `202` only from durable accept paths; reference
  apps that use in-process demos stay explicitly non-CP.
- Event and cursor `/1` shapes are additive-friendly for 0.41 durable history
  and fencing.
- Docs must not describe CP1 as production multi-tenant or claim core directory
  watching.

## Alternatives

| Alternative | Why rejected |
|---|---|
| Infer tenant from path/header alone | Spoofable; violates membership authority |
| Global idempotency key without scope | Cross-tenant collisions and replay |
| `403` for all unauthorized resources | Discloses existence across tenants |
| `BackgroundTasks` as the run worker | Lost on restart; not shared across workers |
| Process-global acceptance dict | Not durable; not multi-worker safe |
| Unversioned SSE event payloads | Blocks 0.41 migration and client stability |
| Core directory-watch extract mode | Couples library semantics to daemons |

## Compatibility

- Additive relative to the shipped thin `etlantic-fastapi` `create_reference_app`
  surface; that adapter remains available and is **not** the CP1 control plane
  (`ETLanticAPI` / `include_router` / `create_app`).
- Wire schemas use `/1` with additive evolution preferred; a `/2` requires
  dual-read guidance.
- Core package version for this ADR freeze wave is **0.39.0**.
- Continuous watch documentation continues to place sensors outside core.
